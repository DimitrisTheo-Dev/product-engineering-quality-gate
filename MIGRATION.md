# Migrate from v1 to v2

Start from a reviewed v2 checkout. Keep the previous caller SHA and adoption commit for rollback.

```sh
node scripts/onboard.mjs --repo /path/to/product --migrate --ref "$V2_RELEASE_SHA"
node scripts/onboard.mjs --repo /path/to/product --migrate --ref "$V2_RELEASE_SHA" --apply
```

The helper recognizes callers generated by v1. It stops on unfamiliar YAML or a conflicting config so you can preserve custom triggers, permissions, and matrix settings. For a customized caller, migrate the inputs using the mapping below and keep its existing workflow structure.

| v1 input                                                                            | v2 location                                                                                      |
| ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `working-directory`, `node-version`, `deep`, `check-timeout-seconds`, `report-name` | Retain as workflow inputs.                                                                       |
| `typecheck-script`, `test-script`, `build-script`                                   | Add to `checks` with the matching kind. `auto` resolves once to `test:ci` or `test`.             |
| `extra-script`                                                                      | The helper retains it as an early check. Put code generation and other prerequisites in `setup`. |
| `product-script`, `smoke-script`                                                    | Add fast checks.                                                                                 |
| `e2e-script`, `security-script`                                                     | Add checks marked `tier: "deep"`.                                                                |
| `react-doctor`, `fallow`                                                            | Add scripts and exact tool pins through onboarding add-ons or your own config.                   |
| `playwright`                                                                        | Add an exact local Playwright dependency and a browser install script in `setup`.                |
| `upload-playwright-failures`                                                        | Rename to `browser-evidence`.                                                                    |

If a required script is absent, pass its actual name or choose an explicit waiver such as `--waive test`. Review workspace package scopes, the config and exact dependency pins, and the generated caller before committing. Update report readers for `schemaVersion: 2`, which uses three statuses and records why checks were skipped.

After the migration, update a v2 caller's pin with `--upgrade --ref "$V2_RELEASE_SHA"`. Review that the diff changes only the SHA and version comment. For rollback, revert the migration commit and restore the corresponding required-check settings. [Detailed configuration](docs/configuration.md).
